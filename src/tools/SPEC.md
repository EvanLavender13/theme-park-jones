# tools

The park's editing tools: what the player's pointer does to the park. A tool never changes the world. It reads intent through sim/park's public queries and geometry (sim/park/SPEC.md). It gives edits, as ParkEdit values, which the app queues for the next cycle, or applies at once while the game is paused (app/SPEC.md). The library tpj_tools links only tpj_sim, so it runs without a window (principle 10).

## Boundary

A ToolState holds one tool, of a ToolKind: None, GuestPath, BackstagePath, PlaceShop, PlaceDepot, PlaceBench, PlaceToilet, MoveBox, EditPath, RemovePoint, Delete, or Furnish. The app drives it with four calls: selectTool, movePointer, pressPointer, and releasePointer. releasePointer puts its edit in an edit the caller keeps. That edit keeps a path's stops while it holds another edit, so switching between a path and another edit frees no memory. movePointer, pressPointer, releasePointer, tentativeEdit, highlightedEntity, the picking queries, frontagePose, editHandles, hoveredHandle, measuredLengths, pathStart, and pathFinish read the park's path points, segments, corners, edges, tapers, boxes, and doors through a ToolPark, which the app keeps. keepToolPark fills it from the world's intent, and the app fills it again whenever an edit, an undo, or a redo applies, or a park is opened. Once its lists have grown, filling it again frees no memory it allocated. A ToolPark also holds the lists the tools reuse from call to call. The app reads tentativeEdit, the edit the ghost shows, which can also fill an edit the caller keeps, and highlightedEntity, the entity the tool marks. boxAt, segmentAt, pointAt, handleAt, and sideAt are the picking queries the tools use. frontagePose gives the pose of a box that fronts paving. editHandles puts the handles Edit path shows in a list the caller keeps, and hoveredHandle gives the one under the pointer. snapGuides gives the guides of the snap in effect, and measuredLengths puts the lengths the app draws in a list the caller keeps. An EditHistory holds the committed edits to undo and redo. clearHistory, noteEdits, undoEdit, and redoEdit change it, and canUndo and canRedo read it. setFurnishChoice sets what the Furnish tool lays: a kind of furniture or none, a spacing, and one side or both. Once a ToolPark's lists and the caller's lists have grown, a frame's tool work frees no memory it allocated while the pointer rests. That covers movePointer with its snap or frontage search, tentativeEdit filling the caller's edit, highlightedEntity, pathStart, pathFinish, editHandles, hoveredHandle, snapGuides, and measuredLengths. A path tool's press that adds a stop asks whether the world accepts the path with lists the ToolPark keeps, so it frees no memory it allocated either. The allocation check holds every tool on full.park to it (decision 0041).

## Input

selectTool changes the tool and drops anything held or drawn without committing it. movePointer records where the pointer meets the ground, or that it meets none, as when it is over a panel, how many meters of ground a screen pixel spans there, and whether snapping is off. It then finds the snap in effect (Snapping). pressPointer and releasePointer are the primary button going down and up.

When the button is released, the tool commits exactly the edit tentativeEdit showed just before, so what the player sees in the ghost is what gets committed. A tool commits its edit whether or not the simulation will accept it, and only the simulation refuses edits (principle 5). A path tool asks the simulation before it adds a stop, as described under Tools. Neither tentativeEdit nor highlightedEntity changes anything.

## Picking

boxAt gives the box whose footprint holds a ground point. segmentAt gives the segment whose width covers the point. If several do, it gives the first in key order. Neither gives the entrance. pointAt gives the path point nearest a ground point, within POINT_REACH. If two are equally near, it gives the one with the lower key.

Each corner (sim/park/SPEC.md, Ground lines) has a radius handle. It lies on the line from the corner's point into the corner, at the arc's middle, but never nearer the point than RADIUS_HANDLE_DEPTH. Each edge that parkEdges gives has an edge handle at its curve's middle. Each taper that parkTapers gives has a taper handle. It lies on the narrower segment's line, where its longest curve starts, but never nearer the place its sides would stop without curves than TAPER_HANDLE_DEPTH, or than the longest any of its curves can be if that is less. handleAt gives the radius, edge, or taper handle nearest a ground point, within HANDLE_REACH. If two are equally near, it gives a radius handle first, then the one with the lower point key, then the lower segment key. A segment's sides are the two lines half its width from its ground line. sideAt gives the segment whose side lies nearest a ground point, within SIDE_REACH. If two are equally near, it gives the one with the lower key.

## Snapping

While a path tool is chosen, the pointer snaps to give the next stop, or the first. While Edit path drags a point, it snaps to give where the point lands. The tool finds the snap whenever the pointer moves and whenever a press or release changes what the tool holds. snapGuides gives the guides of the snap in effect, and measuredLengths gives the segments whose lengths the ghost shows.

Reach is in screen pixels. A snap catches the pointer within SNAP_CATCH_PIXELS of it. Once it has caught the pointer, it holds until the pointer moves more than SNAP_RELEASE_PIXELS from it. A press or a release ends every hold. While snapping is off, nothing snaps: the stop or point lands at the pointer, and no guide shows.

The targets come in four groups. A target in an earlier group beats every target in a later one, and within a group the nearest wins.

1. Points: a path point of the kind, a point an earlier stop of the path being drawn makes, other than the last stop, and a door the kind serves (parkDoors). If a path point's corner is rounded, its target lies at the middle of the arc, where the paving and the route node are, and the stop is that place on the arc (OnBend). If a segment at the corner is left out, the target stays at the point. A door's target lies straight out from the door, half the path's width plus DOOR_CLEARANCE away, so the path ends just clear of the box. A dragged point uses the width of its widest segment. The pointer's distance to a door's target is measured to the line from the door to it. A door has no target when its target lies on the paving of a segment of the kind, within half the segment's width of its ground line, because a path already reaches that door. The segments that move with a dragged point don't count.
2. Crossings: where two guides from different anchors cross, and where a guide crosses the straight part of a segment of the kind.
3. Segments: the straight part of a segment of the kind, the arc of a rounded corner of the kind, and a segment of the path being drawn. Each catches the pointer anywhere within half its width or within reach, whichever is farther, so a press anywhere on its paving joins it. The stop is the nearest place on its ground line, or its end point when that place lies within MIN_SEGMENT_LENGTH of it.
4. Guides: the place on a guide nearest the pointer.

Guides are rays from anchors. While a path is drawn, its last stop is an anchor, and so is its first stop once two stops are drawn. While a point is dragged, the other end of each segment at it is an anchor. From each anchor, guides run straight on, at 45°, at 90°, and at 135° from the direction each segment arrives at it. That includes the segments the anchor ends, the segment or arc it lies on, both ways, and the drawn segments at it, but not the segments that move with a dragged point. If no segment arrives at an anchor, its guides run along the world's axes and their diagonals.

When the stop lands on a guide, it can also snap to a length. If its distance from the guide's anchor lies within reach of a whole number of meters, at least 1, it moves along the guide to that whole length.

Some targets are left out. A path never snaps onto a point or segment of the other kind. A path's next stop never snaps onto a segment that its last stop lies on or ends at, and the path's last stop is left out because a press there finishes the path. A dragged point never snaps onto itself, a segment at it, or a corner with a segment at it.

Each snap in effect shows a guide. A point snap marks the point, and a door snap shows the line from the door to the target. A segment snap shows the segment's straight part, or marks the place on an arc. A guide snap shows the ray from its anchor through the stop, and a crossing shows both of its lines. A length snap shows a tick at each whole meter from its anchor to the stop.

measuredLengths gives a segment from the last stop of the path being drawn to where its next stop would land, while a press would not finish the path. While a point is dragged, it gives a segment from the other end of each segment at the point to where the point would land. Otherwise it gives none.

## Tools

Look (ToolKind None) edits nothing.

Guest path and Backstage path draw a path of their kind. Each click adds the stop the snap gives (Snapping). If the world would refuse the path through the stops so far and that stop, as when it runs through a box, the click adds nothing, and the ghost stays in the invalid tint until the pointer moves somewhere valid. The first click always adds its stop. A click that snaps to a point or segment of the same kind joins the path there, and a segment it joins splits there when the path commits. Where the path crosses a segment of its kind, or itself, both split and share a point there when it commits. Clicking the last stop again finishes and commits the path. The ghost shows the path through the stops and the pointer, and marks each stop that joins a point or segment, and each place where the path crosses one. Before the first click, pathStart gives where that click would start the path and whether it would join a point or segment there, so the ghost can show it. If the drawn path has fewer than two stops, finishing it commits nothing. While a press would finish a path of at least two stops, pathFinish gives its last stop, so the ghost can show that a click there finishes the path.

Place shop, Place depot, Place bench, and Place toilet place a box of their kind at the pointer: a shop, a depot, a bench, or a toilet block. Pressing puts the box down, and dragging before release turns it to face the drag. The next box faces the same way as the last.

Near paving of the kind its front faces, the box fronts that paving instead, in the pose frontagePose gives. A depot's front faces backstage paving, and the front of a shop, a bench, or a toilet block faces guest paving. The box fronts the paving as parkSurface draws it without walkways, at the place on its edge lines nearest the pointer. It faces the paving square to the edge line there, and the middle of its front face lies FRONTAGE_SETBACK outside the paving. Where that place is a corner of the edge lines, the box faces square to the corner's side whose outward direction lies nearer the direction to the pointer, or to the first side along the edge line on a tie. If the corner turns by FRONTAGE_CORNER_TURN or less, as between the short pieces of a curve, and the pointer lies between the outward directions of its two sides, the box faces the corner along the line from the pointer instead, so it turns smoothly around a curve. Along the inside of a curve, where the edge lines turn away from the paving by FRONTAGE_CORNER_TURN or less at each corner, the box fronts a blend of the nearby pieces of that curve, each weighted by how near the pointer it lies, so its place and facing change smoothly there too. A box fits where its footprint overlaps no paving of either kind, every part of its front face lies at least FRONTAGE_SETBACK from all paving, and the middle of its front face lies within CONNECTION_REACH of paving of the kind it faces, so a door there connects. If the box doesn't fit, it keeps its facing and moves the least distance that makes it fit: straight out, away from the paving, by up to FRONTAGE_PUSH, as on the inside of a curve, or along the edge by up to its own width, as beside a junction. If neither fits, it fronts instead the place on the edge lines nearest the pointer where it fits, moved out the same way. It tries places every FRONTAGE_STEP along the edge lines, within twice its own width of the first place, on edges whose outward direction lies within a quarter turn of the first place's. Each place first faces as a pointer the same distance straight out from it would make it face, so the box turns smoothly between places along a curve, and otherwise faces square to its edge. If none fits, it stays at the first place, which the world refuses if the box overlaps paving there. Paving is near when the pointer lies on paving of that kind, or near one of its edge lines. The pointer is near an edge line within FRONTAGE_SETBACK plus the box's depth, or within CONNECTION_REACH plus half the box's depth, whichever is farther. A box placed at the pointer beyond that can't have its door within CONNECTION_REACH of the paving, so a box that would connect always fronts it. If several edge lines are equally near, the box fronts the one that belongs to the lower key. If the box fronts paving when the button goes down, dragging doesn't turn it. While snapping is off, no box fronts paving.

Move box marks the box under the pointer, and dragging moves it, keeping its facing. If the player clicks without dragging, nothing is committed.

Edit path reshapes paths of both kinds. Under the pointer, a radius, edge, or taper handle comes first, then a path point, then a segment's side, then the segment itself. editHandles gives every path point's marker, then every radius handle, edge handle, and taper handle, while Edit path is chosen and nothing is held, so the ghost can show them. While Remove point is chosen and nothing is held, it gives only the markers. hoveredHandle gives the radius, edge, or taper handle, or the segment's sides under the pointer, when a press would take hold of one. The tool marks the path point under the pointer, as pointAt gives it, when no radius, edge, or taper handle is under the pointer.

Dragging a point moves it, and where it lands snaps (Snapping), so a point dropped on a point or segment of its kind, or on a segment's paving, joins it there. The ghost shows every segment the move reshapes, and marks a join with a point or segment, and each place where a moved segment crosses one.

Dragging a radius handle sets the corner's radius. The arc's middle moves as far into the corner as the pointer moves along the corner's halfway line, so the press itself changes nothing. The radius stays between 0 and the largest that fits.

Dragging an edge handle sets that edge's radius. The edge's middle moves as far as the pointer moves along the direction it moves in as the radius grows, so the press itself changes nothing. The radius stays between the smallest and largest that fit.

Dragging a taper handle sets that point's taper length. Where the longest curve starts moves as far as the pointer moves along the narrower segment, away from the point, so the press itself changes nothing. The length stays between MIN_TAPER_LENGTH and the longest any of the point's curves can be.

Dragging a segment's side sets its width: the width at the press, plus twice how far the pointer has moved away from the ground line. The width stays between MIN_PATH_WIDTH and MAX_PATH_WIDTH.

The ghost shows the reshaped segments. If the player clicks a point, a handle, or a side without dragging, nothing is committed. Away from all of these, the ghost marks the place nearest the pointer on the ground line of the segment under it, and a click inserts a point there, as an OnBend when the place lies on an arc.

Remove point marks the path point under the pointer, as pointAt gives it, when exactly two segments use it, and a click removes it with RemovePoint, merging its two segments. If the player clicks away from every point, nothing is committed.

Delete removes the box under the pointer. If there is no box, it removes the segment under the pointer, and any point no other segment uses. The ghost shows what it removes.

Furnish sets the furnishing of the guest segment under the pointer: the first in key order whose width covers the pointer, or, where the pointer lies on other guest paving, as at a junction or on a walkway, the one whose ground line passes nearest it, the first in key order on a tie. Its edit is a SetFurnishing of that segment. With both sides chosen, it gives both sides the tool's choice: its kind and spacing, or no furnishing when the choice has no kind. With one side, it gives the choice to the side of the segment's line the pointer lies on, and the other side keeps its furnishing. The tool marks that segment. Over no guest segment it gives no edit and marks nothing. A click commits the edit.

## History

The history holds a list of edits to undo and a list of edits to redo. Each edit is the intent it changed: the path points, segments, and boxes it removed, those it added, and those it changed, before and after. A box's record holds its kind, pose, and stock setting. A segment's record holds its furnishing. When an edit changes the opening hours, it also holds them before and after, and its reversal sets them back. The entrance never changes.

clearHistory empties both lists and takes the world's intent as the intent the history saw last. noteEdits takes the world after commands were applied, by a cycle or by commitCommands (sim/SPEC.md). It compares the world's intent with the intent the history saw last, then takes the world's intent as the intent it saw last. If nothing changed, it records nothing. Otherwise the change is one edit, even when several commands made it in one cycle. If the change came from an undo, the edit goes on the redo list. If it came from a redo, it goes on the undo list. Any other change goes on the undo list and empties the redo list.

undoEdit takes the last edit off the undo list and gives the RestoreIntent that reverses it. The command removes what the edit added, sets what it changed back to how it was before, and adds back what it removed. redoEdit does the same for the last edit on the redo list, so the command reverses the undo. If there is no edit to take, each gives none. While a command that either gave hasn't been noted, both give none. If noteEdits then sees no change, as when the world refused the command, the edit goes back where it was. canUndo and canRedo give whether undoEdit and redoEdit would give a command.

takeUndo and takeRedo do what undoEdit and redoEdit do, but give the command the history keeps, until its next undo or redo, instead of a copy. Where those give none, they give null. Once the history's lists have grown, taking an undo or redo and noting its change free no memory they allocated. Noting any other edit adds a new change to the undo list and empties the redo list.

What an undo or redo adds back takes fresh keys. If its command applies alone, in its cycle or by commitCommands, noteEdits finds the key each restored record took. From then on, the history uses the new key wherever an edit names the old one.
