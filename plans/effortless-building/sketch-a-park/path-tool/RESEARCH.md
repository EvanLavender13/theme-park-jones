# Research: path-tool

## How does a click-by-click path finish and cancel?

Drawing tools that build a line from clicked points share one pattern. Each click adds a point, the segment from the last point to the cursor follows the cursor as a rubber band, and the line ends by a double-click, a right-click, or Enter, while Escape abandons it. Of these, a double-click needs nothing beyond the left button, and it comes for free if the tool treats a click on the last point as finishing. The first click of the pair adds a point, and the second lands on that point. What the finishing click commits is the drawn points without the rubber band, so the ghost shown while the cursor rests on the last point is exactly the path the click commits, which keeps principle 8's ghost-equals-commit property with no special case. Because the tools see only ground positions, "on the last point" is a ground distance, FINISH_REACH. The finishing click measures it from the snapped cursor, so a double-click lands at distance zero even where snapping moved the point. Finishing on a lone first point leaves too few points for a path, so it ends the drawing with nothing committed. Cancelling needs no gesture of its own: choosing a tool already drops a hold, so it drops the drawing too, and the Tools panel gets a Cancel path button that chooses the same tool again.

Rejected: a right-click to finish, as CAD tools use it, because the right button's drag orbits the camera here and the app would have to tell a click from a drag. Escape and Enter, because keyboard shortcuts are the milestone's deepening candidate. Finish and Cancel buttons alone, which send every path through the panel.

## How does an endpoint snap onto a path of the same kind?

Road and path builders snap a new segment's end onto an existing one when the cursor comes near it, and the natural target is the nearest point of the existing line: the cursor's projection onto each segment, clamped to the segment's ends. Past a path's end, the nearest point is that end itself, so joining end to end falls out of the same rule. Snapping onto the ground line, the one line that is drawn, refused, and walked, puts the endpoint exactly where navigable-networks will look for a junction. The tool snaps the cursor's point whenever it draws, so both the rubber-band end and every clicked point are snapped. Each clicked point was the path's end when it was clicked, and an interior point pulled onto a same-kind path within 2 m lies where the two ribbons already overlap, so snapping it changes nothing the player could have meant otherwise. The ghost shows the snapped points, since the tentative edit holds them.

Rejected: snapping only the first and last points at the moment of finishing, which moves the last point between the ghost and the commit. Snapping to the nearest ground line point only, rather than the nearest point on a segment, which jumps along the line in 1 m steps. Preferring another path's end over its side, which the milestone keeps as a deepening candidate.
